Das Offsite-Backup laeuft jetzt auf **restic** statt BorgBackup - ein Verfahren statt zwei. Der Regelfall ist unser eigener Backup-Server (`rest-server` im Modus `--append-only`): die Instanz darf dort schreiben, aber nichts loeschen, eine uebernommene Maschine kann die Sicherungen also nicht zerstoeren. Angemeldet wird die Instanz mit `odoo offsite register` - das beantragt einen Kundenbereich, ein Admin gibt ihn auf dem Backup-Server frei, danach holt derselbe Befehl Zugangsdaten und Serverzertifikat ab und schreibt sie in die Settings (`OFFSITE_REPO`, `OFFSITE_REST_USER`, `OFFSITE_REST_PASSWORD`, `OFFSITE_PASSPHRASE`). Bringt die Maschine ihre Passphrase schon mit (Shop/zCICD legen sie je Projekt im Backend ab), bleibt diese die Wahrheit und der Server erzeugt keine zweite. Die Vollstaendigkeitspruefung bleibt: ohne Datenbankstand (Barman oder Dump) bricht der Lauf ab, statt ein Archiv anzulegen, das aussieht wie ein Backup. Aufbewahrung ist bei append-only-Zielen Sache des Backup-Servers; `odoo offsite prune` sagt das dort auch. Statt `odoo offsite borg` gibt es `odoo offsite restic` als Notausgang. Ziele: `rest:https://...` (Backup-Server), `sftp:...` (z.B. Hetzner Storage Box) oder ein Pfad auf einer eingehaengten Platte.
