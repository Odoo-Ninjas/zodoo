`odoo unittest <file>` no longer reports success for a test file that odoo never ran. Odoo's `--test-file` only collects the test modules imported in the addon's `tests/__init__.py`, so a file missing there was skipped without a word and the run still exited 0. The command now checks that import up front and fails with a pointer to the missing `from . import <file>`. It also raises the log handlers for `odoo.service.server`, `odoo.tests` and `odoo.tests.result`, so a run states which tests it executed instead of staying mute behind the `:WARN` handler of `config_unittest`.
