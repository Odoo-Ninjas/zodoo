`odoo filestore dedup` (and the dedup step of `sync`) now only pools files whose name is a content hash (`<xx>/<40 or 64 hex>`). Deduplication rests on "equal name means equal content", which is true for content-addressed attachments and for nothing else - a forgotten dump or an editor backup inside a filestore directory could carry the same name in two databases with different bytes, and adopting it hardlinked both to one inode: one instance would silently read the other's data, with no error anywhere. Such files now stay in their own database's directory and are reported as `not pooled (no attachment name)`.
