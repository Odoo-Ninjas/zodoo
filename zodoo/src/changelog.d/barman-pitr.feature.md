New optional `barman` service for PostgreSQL backups with point-in-time-recovery. Enable with `RUN_BARMAN=1` (off by default, and forced off on DEVMODE machines unless `BARMAN_FORCE_IN_DEVMODE=1`). The barman container streams WAL continuously over a replication slot (no SSH) and a daily full base backup runs via the cronjobs daemon. New CLI: `odoo barman backup|list|status|check|switch-wal` and `odoo barman recover [BACKUP_ID] [--target-time "YYYY-MM-DD HH:MM:SS" | --target-name <restore-point>]` for plain restore or point-in-time-recovery (auto-promotes to read-write at the target). Run without arguments, `odoo barman recover` shows an interactive picker: choose a base backup, or enter an absolute timestamp, an age (`30m`, `2h`, `1d` — computed back from now), or a named restore point. For a timestamp/age target the matching base backup (newest at or before the target) is selected automatically. Recovery is built in a sibling datadir and swapped in atomically, keeping the previous datadir as `pgdata.prev` for rollback; afterwards postgres is promoted and the whole stack is brought back up. `BARMAN_MAX_SLOT_WAL_KEEP_SIZE` caps slot WAL retention so a long barman outage cannot fill the primary's disk. `BARMAN_GUARD_UPDATE=1` makes every `odoo update` set a PITR safepoint first and offer a one-key DB rollback if the update fails. Coexists with the existing `pg_dump`-based `odoo backup/restore odoo-db`.
