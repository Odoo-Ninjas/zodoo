Settings files that contain a secret (`*PASSPHRASE*`, `*PASSWORD*`, `*SECRET*`, `*TOKEN*`, `*PRIVATE_KEY*`) are now written with group and other permissions removed. They previously landed on whatever the umask gave (often `0644`) and were protected only by the permissions of the home directory — on a machine with several instance users a home created as `0755` left the offsite backup passphrase readable. Writing a settings file also no longer resets its permissions to the umask: the existing mode is carried over to the replacement file. System-wide settings outside the home (`/etc/odoo/settings`) are deliberately left alone, since every instance has to be able to read them.
