Enabling Barman (`RUN_BARMAN=1`) on an instance whose database already existed left PostgreSQL without the `host replication` entry in `pg_hba.conf`, because that entry was only added by an initdb-phase script. The result was a silent standstill: `wal_level` was set, the barman container was running, but WAL streaming and base backups failed with "no pg_hba.conf entry for replication connection" — visible only when someone ran `barman check`. The entry is now ensured idempotently on every start of the postgres container, before postgres comes up, using the same auth method as the existing host line.
