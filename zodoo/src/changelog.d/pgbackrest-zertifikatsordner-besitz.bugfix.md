`odoo pgbackrest info` and `check` no longer fail with `[CryptoError] unable to set user-defined CA certificate location` after the certificates have been rewritten. The sidecar's entrypoint hands `/etc/pgbackrest/cert` to the pgbackrest user (uid 999), but only at container start; `odoo pgbackrest register` runs as the operating user and writes the files back to its own ownership, leaving a 0700 directory that uid 999 cannot enter. The message points at a broken certificate and is nothing of the sort. Worse, it is asymmetric: the backups themselves kept running, so only the commands one uses to *check* whether anything is still being backed up went blind. The ownership is now restored before every pgbackrest command instead of only at start-up, silently when it is already right and with one line when it had to be corrected; if the repair itself fails, the command proceeds as before rather than being blocked by it.
