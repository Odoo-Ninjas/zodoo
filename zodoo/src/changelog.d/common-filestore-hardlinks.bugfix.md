`ODOO_FILES_COMMON=1` now shares the attachment filestore via hardlinks instead of replacing every `filestore/<db>` by a symlink to `filestore/_common`. The symlink also shared Odoo's garbage-collection checklist, so the nightly autovacuum of one database deleted the freshly written attachments of every other instance on the host - resulting in missing images and HTTP 500 on `/web/assets/...` bundles (login page without JS = no login). Hardlinks keep the space saving, but every database gets its own `checklist` again and a GC run only drops its own link. Existing symlinks are left in place and reported; `odoo filestore unshare` migrates them without using extra disk space, `odoo filestore dedup` re-links per-database filestores into the pool.
