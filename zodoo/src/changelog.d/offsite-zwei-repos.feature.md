Offsite backups now write **two** repositories per customer area instead of one: `<area>/db` for the database (Barman catalog or dump) and `<area>/files` for the filestore, tagged `zodoo,db` / `zodoo,files`. Both share the area's credentials and passphrase, so it stays one secret per project. The point is monitoring: with everything in one repository an arriving filestore hid a database dump that had stopped coming, because the area still looked freshly written — now each half has its own age and the backup server alarms per half. `odoo offsite list|info|check|init` report on both and say which one they are showing; `odoo offsite restic` picks a repository with `OFFSITE_STREAM=db|files` (default `db`). `OFFSITE_LAYOUT=flat` keeps the old single-repository behaviour for existing installations.

The completeness check now works in both directions: as before the run aborts when no database state would end up in the snapshot, and it now also aborts when the filestore is missing or empty — that is what an unmounted volume looks like, and it would leave the database saved but the attachments gone, noticed only on restore. `OFFSITE_ALLOW_WITHOUT_FILES=1` is the deliberate way out for an instance without attachments. Both streams are attempted even if one fails, so a broken database upload no longer masks a broken filestore upload.
