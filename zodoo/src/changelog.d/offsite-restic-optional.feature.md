With **both** streams on the write-only path, restic is no longer used at all — and an offsite run no longer demands `OFFSITE_REPO` or `OFFSITE_PASSPHRASE`. Clearing both settings is now a supported configuration: `odoo offsite backup` runs the database and filestore streams and needs nothing else. That removes the most expensive secret in the setup from such machines — the passphrase that decrypts the entire backup history.

On the backup server the old repositories should be taken out of monitoring with `restic-area retire <area>`, which *moves* `db/` and `files/` aside rather than deleting them. Without that, nobody writes to those streams any more and the per-stream "no backup for 48 h" alarm fires from the next day onwards for ever. Deleting is deliberately not offered here: it would be irreversible, and the old stock is worth keeping until the write-only path has proven itself over time.
