The minutely WAL job was defined on **every** instance, whether or not a write-only database target existed. It returns immediately in that case, but it still starts the CLI — measured at 0.44 s per start, so roughly ten minutes of CPU per day on each instance that does not use it, and about 18 CPU-hours a day across a hundred instances. The job is now dropped entirely unless both `OFFSITE_WO_URL` and `OFFSITE_WO_DB_RECIPIENT` are set (an empty `CRONJOB_*` value is skipped by the cron daemon, so this removes the job rather than breaking it).
