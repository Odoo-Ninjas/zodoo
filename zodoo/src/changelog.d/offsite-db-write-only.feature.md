The database can now take the same write-only path as the filestore: with `OFFSITE_WO_DB_RECIPIENT` set, barman base backups and WAL segments are encrypted to an **age public key** and pushed to a receiver that only accepts uploads. The machine holds no private key, so it can neither read nor delete its own backups — closing the gap the restic path cannot, where deduplication needs the repository index and therefore a readable key on the machine.

It works because both sources are immutable: a WAL segment is written once and never changes, a base backup never changes once barman marks it `DONE`. So there is nothing to deduplicate and no reason to read the target. New commands `odoo offsite db` (base backups + WAL) and `odoo offsite wal` (WAL only, every minute via `OFFSITE_WAL_CRON`), so losing a machine costs a minute of transactions rather than a night. The segment currently being written (`*.partial`) is never uploaded. The minutely job uses its own container name and a lock in the state directory, so it stays a quiet no-op while a nightly base backup upload is running instead of failing every minute.

Two consequences beyond confidentiality: WAL completeness is now checkable **without any key**, because object names are in the clear and the manifest declares `begin_wal`/`end_wal`/`timeline` per base backup — in a restic repository even the file names are encrypted, so only a key holder could notice a broken chain. And retention becomes possible at all: whole generations can be dropped by name, while an append-only restic repository cannot be pruned because `forget --prune` needs the repo key.
