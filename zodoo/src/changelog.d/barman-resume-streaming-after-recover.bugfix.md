WAL streaming no longer stops silently after `odoo barman recover`. A recovery changes the timeline while `pg_receivewal` is still holding a `.partial` of the old one, so the replication slot stayed uninitialised, nothing archived WAL any more, and the next `barman backup` failed with "Impossible to start the backup" — with nothing in between saying so. The recover now resets the receiver itself, and the same thing is available as `odoo barman receive-wal-reset` if it ever has to be done by hand.
