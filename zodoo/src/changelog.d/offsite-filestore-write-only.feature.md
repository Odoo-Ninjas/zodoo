New write-only path for the filestore: with `OFFSITE_WO_URL` and `OFFSITE_WO_RECIPIENT` set, the filestore no longer travels through restic but is pushed to a receiver that only accepts uploads — and the bundle is encrypted to an **age public key**, so the machine cannot read even its own backups, and cannot delete them either. That closes the one gap the restic path cannot: deduplication needs the repository index, the index is encrypted, so a machine that can back up can also read its whole history.

It works because Odoo already names every attachment after the SHA-1 of its content: a file is written once and never changes, so "what is new?" is a pure name comparison against a **local ledger** (`$HOST_RUN_DIR/offsite.state/filestore.ledger`) — no repository index, no key, no chunking. New files go up as one bundle per run plus a manifest listing bundles and their checksums (never file names: a name is the hash of its content, so a name list would let someone confirm whether a known document is in the backup). New command `odoo offsite filestore`; when a write-only target is configured it replaces the restic `files` stream instead of running beside it. Restoring needs the age private key, which belongs in 1Password.
